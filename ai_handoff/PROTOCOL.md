# Working protocol: Claude and Codex on one repo

Anthony has both of us improving the same deliverables. This is how we avoid
destroying each other's work. Read section 1 before editing anything.

Branch: `analytics-platform`. Both of us push here. Pull before you push.

---

## 1. The one thing that will destroy your work

**Most of the deliverables are GENERATED, not authored.** If you hand-edit a
generated file, the next `python run_all.py` overwrites it without warning and
your changes are gone. This is not hypothetical — it is how the repo is built.

### Generated — do NOT hand-edit. Edit the generator instead.

| Artefact | Regenerated by |
|---|---|
| `dbt_redandyellow/models/**` (all 36 models, every .yml, every test) | `generator/scaffold_dbt.py` |
| `dbt_redandyellow/dbt_project.yml`, `profiles.yml`, `macros/**` | `generator/scaffold_dbt.py` |
| `powerbi/RedAndYellow.SemanticModel/**` | `powerbi/build_pbip.py` |
| `powerbi/RedAndYellow.Report/report.json` | `powerbi/build_report.py` |
| `powerbi/RedAndYellow.Report/StaticResources/**` (the theme) | `powerbi/build_report.py` |
| `powerbi/data/*.parquet` | `powerbi/export_marts.py` |
| `ebook/RedAndYellow_Data_Story.docx` | `reporting/build_ebook.py` |
| `ebook/RedAndYellow_Data_Story.pdf` | `reporting/export_pdf.py` |
| `ebook/figures/*.png` | `reporting/capture_evidence.py`, `capture_infra.py`, `capture_model.py` |
| `reporting/RedAndYellow_Analytics.xlsx` | `reporting/build_excel.py` |
| `reporting/salesforce_export/**` | `reporting/export_salesforce_data.py` |
| `data/crm_load/*.csv` + its import plan | `salesforce/prepare_crm_load.py` |
| `nifi/FLOW_MAP.md` | `nifi/show_tree.py` |
| `warehouse/**` | `generator/generate.py` + dbt (gitignored) |

**`scaffold_dbt.py` is the sharpest edge.** It deletes and rewrites the entire
`models/` tree. A hand-edited SQL model survives exactly until the next run.

### Authored — safe to edit directly

- Every script in `generator/`, `powerbi/`, `reporting/`, `salesforce/`,
  `nifi/`, `fabric/`, `ml/`
- `PLATFORM.md`, `README.md`, `HANDOFF_FROM_CLAUDE.md`, `salesforce/SETUP.md`,
  `docs/**`, `erds/**`
- `ai_handoff/**`
- `tools/import_salesforce.py` (originally yours; I patched it in place and
  documented every change in `HANDOFF_FROM_CLAUDE.md` §"What changed")

### So: to change a chart, change `build_report.py`, then re-run it.

```bash
python powerbi/build_report.py          # rewrites report.json + theme
python reporting/build_ebook.py         # rewrites the docx
python reporting/export_pdf.py          # then the pdf
python generator/scaffold_dbt.py        # rewrites models/, then: dbt build
```

If you genuinely need a file to stop being generated, say so in a handoff note
and I will take it out of the generator rather than us fighting over it.

you now consider yours.** I will read it before my next build and stay out of
those.

## 4. Before you push

```bash
git pull --rebase origin analytics-platform
```

Two hazards already paid for:

- **`.pbi/cache.abf` reaches ~196 MB** when Power BI Desktop opens the project,
  and GitHub rejects the push at its 100 MB limit. It is gitignored now — do not
  un-ignore it.
- **Power BI Desktop upgrades the report format on save**: it writes
  `definition/pages/**`, sets `definition.pbir` to version 4.0, deletes
  `report.json`, and removes `StaticResources/` — so the theme disappears and
  everything renders in default blue. `build_report.py` now clears that and
  re-asserts the legacy format. If you would rather generate PBIR 4.0 natively,
  that is the better fix and it is yours to take.
